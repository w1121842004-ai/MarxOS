# MarxOS 开发日志

2026-05-17

---

## 1. 本轮目标

本轮目标是把 MarxOS 从“能检索”推进到“关键出处问题可信回答”：

- 书目定位必须走本地确定性逻辑。
- 精确引文出处必须走本地确定性逻辑。
- 不确定的书名或伪造引文不能用向量候选冒充可靠答案。
- 页码引用必须保守，不能把 OCR 噪声误报为印刷页。
- app 主入口要可导入、可测试，便于继续收敛质量。

## 4. 当前可信基线

MarxOS 现在有三条确定性保护线：

1. 书目定位：本地核心书目回答。
2. 精确引文：本地 OCR cache 精确匹配回答。
3. 不确定内容：明确拒绝确认，不把向量候选冒充出处。

这让后续的概念解释、理论分析和长文回答可以建立在更稳的出处层之上。

## 7. 5.17 追加记录：MEA 页码可信度与重建计划

### 7.1 问题确认

5.17 后续排查确认，`mea01.pdf` - `mea10.pdf` 这组补卷材料多数属于图片 PDF。旧 OCR cache 主要保存整页文本，缺少每行坐标，因此构建向量库时只能从整页文本的开头/结尾猜测页码。

这会造成两个问题：

1. 页眉/页脚中的真实页码有时被 OCR 合并进正文行，不是独立数字行。
2. 正文注释、手稿内部页码、参考页码也会出现在页边或行尾，容易被误判成印刷页。

因此，`printed_page` 不能只靠“看到一个数字”判断，必须区分数字来自页眉/页脚还是正文/注释。

### 7.2 今日新增的页码诊断与保护

- 新增 `scripts/detect_printed_page_start.py`，用于扫描每本书前若干页，寻找稳定的 PDF 页到印刷页 offset。
- 抽样结果显示：
  - `capital.pdf`、部分 `meXX.pdf` 可以找到长连续 offset，适合自动生成高置信页码锚点。
  - `mea01.pdf`、`mes01.pdf` 等只出现短连续段，且证据行疑似正文注释或手稿页码，不应直接信任。
- `app.py` 对 `mea/mes` 来源的旧 `printed_page` 增加保守保护：低可信时 citation 回退为 `PDF第X页`。
- 新增 `rag/page_number_detection.py`，集中处理页码候选识别规则。
- 修改 `rag/ocr_to_cache.py`：后续重新 OCR 时保留 PaddleOCR 的坐标框，并输出：
  - `layout_lines`
  - `header_text`
  - `body_text`
  - `footer_text`
  - `page_number_candidates`
- 修改 `rag/build_vectorstore_from_cache.py`：构建向量库时优先使用 OCR 阶段分离出的页眉/页脚页码候选，同时保留：
  - `page_number_source`
  - `page_number_candidates`
