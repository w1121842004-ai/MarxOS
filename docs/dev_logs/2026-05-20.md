# MarxOS 开发日志

2026-05-20

---

## 1. 本轮目标

本轮目标是把 MarxOS 从“能给答案”继续推进到“网页端可用、证据链可核、页码更稳、评测可回归”：

- Web 端交互要更接近主流大模型网页端，支持新对话、历史记录和独立滚动。
- 回答中的引用必须从正文里拆出来，用脚注和底部引文注释承载。
- “查看证据”必须展示最终答案真正引用到的证据，不能把检索候选混进去。
- printed page 引用必须优先于 PDF 页，且不能把 OCR 噪声误报成真实页码。
- 向量库不能再大量依赖固定窗口半截 chunk，要尽量回到更稳定的语义段落。
- 评测要能覆盖经典引文、概念出处、拒答场景和页码专项回归。

## 2. 主要变更

### 2.1 Web 端对话体验改造

- `web_app.py` 调整为更接近主流大模型网页端的布局。
- 默认打开页面时进入新对话窗口。
- 只有用户真正发送问题后，当前对话才写入左侧历史记录。
- 左侧历史栏与右侧对话区拆成独立滚动区域，避免历史栏和聊天区互相拖动。
- 保留会话切换能力，点击左侧历史可恢复既有对话。

### 2.2 回答格式与引文规范化

- `app.py` 收紧回答格式，避免回答只有一小段、结构松散的问题。
- 将原先插在正文中的长书目信息改为脚注式引用。
- 底部统一输出“引文注释”，不再让来源信息打断正文阅读。
- 禁止继续输出 `pdf_page`、`PDF第X页` 这类字段。
- 去掉“同上”写法，避免多个脚注在人工核查时失去定位意义。
- 删除不应出现的伪出版信息，只保留当前语料能支持的版本信息。

### 2.3 证据链修正

- `app.py` 修复 evidence 面板语义错误。
- 旧逻辑会把前 12 个检索候选直接展示给前端，导致用户看到大量无关证据。
- 新逻辑只返回最终答案脚注真正命中的证据。
- 增加答案脚注与 evidence 的匹配函数，防止“答案写了页码，证据却对不上”。
- evidence 标题默认改为更干净的书目信息，减少 OCR 噪声短句进入证据摘要。
- 增加 citation audit，检查：
  - 是否出现禁止字段
  - 是否存在脚注但无对应证据
  - 脚注是否能与后端 evidence 对齐

### 2.4 页码映射与引用页修正

- `app.py` 引入 `page_map.json` 的 printed page 映射优先级。
- 新增 `scripts/build_page_map.py`，用于从 OCR 页边信息构建 PDF 页到 printed page 的映射。
- 新增 `scripts/evaluate_citation_pages.py`，用于关键句页码回归。
- 对 citation page 的推断增加正文重定位逻辑，不再只用用户问题去匹配页面。
- 现在优先使用“证据正文”和 OCR 页面做重合打分，再决定 printed page。
- 修正了“辩证法暂时性”案例，第三句稳定落在第 270 页。

### 2.5 语义段落 chunk 与段落向量库

- `rag/paragraph_cache.py` 修复中文句末和标题识别规则失效的问题。
- 重新收紧段落切分逻辑，尽量按照语义段落而不是固定窗口切块。
- 新增目录/噪声过滤，去掉：
  - 连续感叹号页
  - 目录点线
  - 无 printed page 的目录型页面
- 避免索引页、书目页、目录页污染段落向量库。
- 回答主检索改为“段落向量库优先，旧 chunk 向量库兜底”。
- 为段落候选增加词面重合门槛，防止纯向量相似度把无关页拉到前排。

### 2.6 段落缓存与向量库重建

- 重新生成 `data/paragraph_cache_core.jsonl`。
- 核心 14 个来源共生成 42517 条语义段落。
- 重新构建 `vectorstore/marx_reader_paragraph`。
- 之前一次构建在 89.82% 时因为超时中断，随后提高超时时间后完成全量重建。

### 2.7 评测集与回归脚本

- 保存 50 条测评样例到 `eval_dataset.json`。
- 新增 `scripts/evaluate_eval_dataset.py`，用于自动评测 50 条样例。
- 新增 `scripts/audit_ocr_printed_pages.py`，用于 OCR 页码审计。
- 将“两个结合”“社会主义核心价值观”“新质生产力”等拒答类问题纳入评测。
- 将页码专项回归和 smoke check 继续保留在本地验证流程中。

### 2.8 借鉴成熟 RAG 项目的落地调整

- 参考 PaperQA2、LlamaIndex CitationQueryEngine、Haystack 的思路，进一步收紧证据流转。
- 把“检索候选”“最终回答使用证据”“前端展示证据”明确拆层。
- 优先保证 citation 可审计，而不是只追求回答看起来完整。
- 在检索后处理阶段加入更强的规则校正，而不是完全依赖向量相似度。

## 4. 当前可用基线

MarxOS 目前已经形成四条更稳的可用基线：

1. Web 端交互基线：新对话、历史记录、独立滚动、证据查看基本可用。
2. 引文输出基线：正文与脚注拆分，底部统一引文注释，不再混入 `pdf_page`。
3. 证据可信基线：前端展示的是最终答案实际引用证据，不再是检索候选集合。
4. 页码与检索基线：printed page 优先，段落向量库优先，旧 chunk 库作为兜底。

这意味着后续继续优化回答质量时，可以更少地被“前端像对了但证据不对”“页码看起来对但其实漂了”这类问题反复拖住。

## 5. 已知风险

- Windows PowerShell 当前仍会输出 profile 执行策略报错；不影响脚本结果。
- 终端中文显示仍有 mojibake，UTF-8 文件本身正常，但 PowerShell 里阅读体验较差。
- 50 条评测集全部通过，不代表页码问题已经彻底消失，尤其是长分析问答和跨页段落仍需继续补样例。
- 段落向量库虽然已过滤一批目录页和噪声页，但个别非正文页面仍可能通过相似度进入候选。
- Web 端修改后仍需要重启服务，代码更新不会自动反映到旧页面进程。
- `HuggingFaceEmbeddings` 目前仍有 LangChain 弃用警告，后续可以迁移到 `langchain-huggingface`。

## 6. 建议下一阶段

下一阶段可以继续做“证据质量层”和“网页稳定层”：

1. 扩大页码专项评测集，把用户真实发现的错页案例沉淀成固定回归样例。
2. 对目录页、索引页、书目页建立更强的页面分类与过滤规则。
3. 增加 evidence 命中率、脚注一致性、页码可信度等专门报表。
4. 优化 Web 服务重启与部署流程，减少“代码改了但前端没生效”的确认成本。
5. 继续补充经典篇目、经典语句与 hard negative，提升马克思主义文献问答场景下的稳定性。
