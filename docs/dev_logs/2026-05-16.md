## 1. 今日目标

本次开发的核心目标是把 MarxOS 从“全集大范围探索”收束到一个更可控的小项目范围：

```text
mea01.pdf - mea10.pdf
mes01.pdf - mes04.pdf
```

也就是先围绕《马克思恩格斯文集》相关卷册和《马克思恩格斯选集》相关卷册做稳定检索，不再一开始就处理整个《马克思恩格斯全集》的复杂目录结构。

具体目标包括：

- 修复 OCR 清洗导致目录行粘连的问题。
- 新增页级 OCR 清洗模块，区分目录页、标题页、正文页。
- 重建小语料库 OCR cache 和向量库。
- 为目录条目补充 `level` / `parent` 层级信息。
- 增加核心经典篇目白名单，提高篇目定位稳定性。
- 增加精确引文检索，避免短引文完全依赖向量检索。
- 建立围绕 15 篇核心经典和若干名句的评测流程。

### 2.3 修复 OCR 换行被吞导致目录粘连的问题

用户指出 `mea06/page_8.txt` 中出现：

```text
91 III.货币积累
```

被错误识别/清洗为：

```text
91111.货币积累
```

根因是旧的 OCR 清洗逻辑会删除所有换行和空白，导致上一行页码和下一行罗马数字标题粘在一起。

已修复为：

- 保留页内换行。
- 每行单独清理空白。
- 修正行首常见 OCR 误识别：

```text
111. -> III.
11.  -> II.
```

相关提交：

```text
91f78ee Preserve OCR line breaks
```

验证结果：

- `mea06/page_8.txt` 不再出现 `91111`。
- “II. 积累和规模扩大的再生产 91”和“III.货币积累 96”能分行保留。

### 2.4 新增统一 OCR 清洗模块

新增文件：

- 根据大量点线、页码区间、行尾页码判断目录页。
- 根据短文本、作者名、篇名判断标题页。
- 保留 `raw_text`，同时生成 `cleaned_text`。

### 2.5 改造 OCR cache 存储结构

修改文件：

- `rag/ocr_to_cache.py`

现在每页会保存两种缓存：

```text
page_N.txt
page_N.json
```

其中：

- `page_N.txt` 保存 `cleaned_text`，兼容旧流程。
- `page_N.json` 保存完整结构，包括 `raw_text`、`cleaned_text`、`page_type`、识别原因等。

这让后续向量库构建可以知道某页到底是目录页、标题页还是正文页。

### 2.6 改造向量库构建流程

修改文件：

- `rag/build_vectorstore_from_cache.py`

新增逻辑：

- 优先读取 `page_N.json`。
- 旧 `.txt` 缓存仍可兼容读取。
- `page_type == "toc"` 的页面跳过，不进入正文向量库。
- `page_type == "title_page"` 不单独入库，而是记录篇名/作者上下文。
- 后续正文 chunk 可以使用最近标题页补充 title metadata。

这一步减少了目录页污染正文检索的问题。

### 2.12 改进短引文和跨行片段定位

调试中发现“工人没有祖国”只有 6 个汉字，最初设置的最短匹配阈值过高，导致被过滤。

已将规范化后的最短引文长度阈值从 8 降到 5。

同时，OCR 文本常出现跨行断句。今天将 snippet 定位改成：

```text
原文字符
-> 规范化字符
-> 保留规范化字符到原文位置的映射
-> 根据规范化命中位置回推原文位置
```

这样即使引文跨行或标点不完全一致，也能把命中句放进预览片段中。

## 6. 当前遗留问题

### 6.1 negative 测试仍会硬返回候选

如果用户问：

```text
《一个不存在的马克思著作标题》收录在哪一卷？
请给出“这是一句随便编造的引文”的准确页码。
```

系统仍会在精确匹配失败后回退到向量检索，并给出相似但不正确的候选。

下一步需要增加“无答案判定”：

- 精确匹配失败。
- 核心经典表无命中。
- 向量召回相似度不足。
- metadata 不满足题目约束。

满足这些条件时，应明确回答“未找到可靠出处”，而不是强行给结果。

### 6.2 印刷页码和 PDF 页码仍存在偏移

核心经典表里记录的是更接近“印刷页码”的范围，但 OCR cache 的 `page_N.json` 是 PDF 页序。

因此精确引文检索不能只扫描核心范围，还需要在范围未命中时进行全局回退扫描。当前已实现回退机制，但后续仍需要显式建模：

- PDF 页序。
- 印刷页码。
- 引用页码。

### 6.3 部分篇目 metadata 仍受 OCR 目录噪声影响

虽然目录页已经被跳过，核心篇目也有白名单，但部分 `article` 或 `section` 仍可能来自 OCR 错误目录项。

后续需要继续提高 metadata 的可信度，尤其是：

- 注释页。
- 索引页。
- 年表页。
- 插图说明页。

### 6.4 核心经典页码表仍需要人工审校

`rag/core_classics.json` 已明显提升稳定性，但仍需要后续人工校对：

- 每篇核心经典的主版本。
- 节选版本。
- 起止页码。
- 常见名句所在页。

## 7. 下一步计划

### 7.1 做无答案判定

下一步优先级最高。

目标：

- 不存在的标题不要硬返回相似篇目。
- 编造引文不要硬返回相似句子。
- 引文类问题如果 exact lookup 找不到，应先提示未找到精确匹配，再给可选候选。

### 7.2 为 quote lookup 增加置信度字段

建议 metadata 增加：

```json
{
  "match_type": "exact_quote",
  "confidence": 1.0
}
```

向量检索结果可以设置较低置信度。回答时根据置信度决定是否直接给出处。

### 7.3 继续修正页码系统

需要把：

```text
pdf_page
printed_page
citation_page
```

区别得更清楚，避免把 PDF 页序误当成正式引用页码。

### 7.4 建立人工审校流程

建议后续把 `core_classics.json` 导出为更易审校的表格格式，用于校对：

- 篇名。
- 作者。
- 主版本。
- 起止页。
- 名句页码。

## 8. 今日总结

本轮开发把 MarxOS 从“能检索”推进到更接近“能可靠定位”的阶段。

系统已经形成三层检索结构：

```text
核心篇目白名单
精确引文匹配
向量语义检索
```

同时 OCR cache 也从单纯 `.txt` 文本升级为包含 `raw_text`、`cleaned_text`、`page_type` 的结构化页面数据。

这对马克思主义原著这种需要严肃出处、页码和篇目定位的学术场景非常关键。下一步不应继续盲目增加召回，而是要让系统学会“不知道就不答”，优先解决不存在标题和伪造引文的无答案判定问题。
