## 1. 当日概览

今天的工作重点是以“真实 Web 用户 + 马克思主义主题问答”的方式对网站进行连续实测，并围绕实际暴露的问题做修复，而不是只在本地脚本链路上验证。

本轮主要解决了三类问题：

- Web 端旧会话历史污染新问题，导致同一句问题在旧对话里被带偏。
- 专题问答直接把 OCR 半截原句端上来，出现开头句号、作品名前缀、杂字符和半截语义。
- 明确作品名的问题（如《共产党宣言》）会被更大专题盖过去，或者在外部模型波动时直接返回 500。

## 2. 主要问题与修复

### 2.1 修复 Web 端历史污染

问题：
- 即便用户重新发起一个新问题，后端仍会把旧历史拼进 contextual query。
- 这会让“请列出十段马克思关于农民合作社的观点”在旧对话里再次掉回错误路径。

修复：
- 修改 [web_app.py](/c:/Users/Administrator/Desktop/MarxOS/web_app.py)，只有明确追问时才拼接历史上下文。
- 普通新问题直接使用当前 query，不再自动拼接历史。

结果：
- 同一句问题在“新对话”和“旧对话”中都能稳定回到正确路径。

### 2.2 修复日志输出阻塞 HTTP 响应

问题：
- Windows PowerShell 控制台在输出中文 metrics 时可能触发编码异常。
- 这会导致日志已经写入，但 HTTP 响应没有及时发送，浏览器表现为超时或长时间等待。

修复：
- 修改 [web_app.py](/c:/Users/Administrator/Desktop/MarxOS/web_app.py)，对中文 metrics 的控制台输出增加 `try/except UnicodeEncodeError` 兜底。
- 在控制台不支持中文时自动退回 `ensure_ascii=True` 输出，避免影响响应链路。

结果：
- `/api/ask` 的真实 HTTP 调用恢复稳定，不再因为控制台编码问题卡住响应。

### 2.3 压缩首问耗时

问题：
- 专题首问此前存在向量库/embedding 重复加载，首次响应非常慢。

修复：
- 在 [app.py](/c:/Users/Administrator/Desktop/MarxOS/app.py) 增加 embeddings、主向量库、段落向量库的进程级缓存。
- 在 [web_app.py](/c:/Users/Administrator/Desktop/MarxOS/web_app.py) 启动时预热主库和段落库。
- 对专题首问跳过不必要的段落库二次检索。

结果：
- 农民合作社专题首问已压到亚秒级，实测约 0.3s。

### 2.4 修复专题答案直接暴露 OCR 脏文本

问题：
- 农民合作社专题答案此前直接截取 OCR 原句，出现：
  - 开头是句号
  - “法德农民问题 要……”这类作品名前缀残留
  - `z`、`f` 等 OCR 杂字符
  - 半截原句像摘录草稿，不像观点整理

修复：
- 在 [app.py](/c:/Users/Administrator/Desktop/MarxOS/app.py) 新增：
  - `clean_excerpt_for_display()`
  - `best_excerpt_span()`
  - `summarize_peasant_cooperative_viewpoint()`
  - `format_topic_viewpoint()`
- 让专题首问先清洗证据片段，再改写成“观点句”，而不是直接回显 OCR 句头。
- 同时调整 `topic_direct_evidence()` 和 `topic_answer_evidence()` 的排序，让《法德农民问题》优先级高于泛化或噪声页段。

结果：
- 农民合作社答案不再以“。同样……”开头。
- 前排答案已经变成较完整的观点句，例如：
  - “分散的小块土地应结合起来实行较大规模经营，并通过合作社方式重新组织生产。”
  - “单靠减轻债务和保全小块土地并不能真正解放农民，关键是为其转向新的合作经营形式创造条件。”

### 2.5 修复“明确作品名”被大专题劫持

问题：
- 类似“请概括共产党宣言关于阶级斗争的观点”这类问题，虽然点名了作品，但会被 `social_analysis` 这类更大的专题盖掉。

修复：
- 调整 [app.py](/c:/Users/Administrator/Desktop/MarxOS/app.py) 中 `constraints_from_query()` 的优先级：
  1. 显式书名/书目定位
  2. locator entries / core classics
  3. 主题专题匹配
- 这样明确作品名时，优先收敛到作品本身，不再先走大专题。

结果：
- 《共产党宣言》相关问法不再被“社会分析”专题抢走。

### 2.6 为“严格作品名 + 列观点”增加本地稳定生成路径

问题：
- 明确作品名的问题如果要求“概括/归纳/列观点”，此前通常仍依赖外部模型。
- 一旦模型侧抖动，就会在 Web 端返回 500 或出现不稳定结果。

修复：
- 在 [app.py](/c:/Users/Administrator/Desktop/MarxOS/app.py) 增加：
  - `is_view_list_query()`
  - `strict_title_answer_evidence()`
  - `build_strict_title_view_list_answer()`
- 对“明确作品名 + 列观点/概括”场景，先做本地证据筛选，再本地生成结构化观点答案，不必强依赖外部模型。

结果：
- “请概括共产党宣言关于阶级斗争的观点”现在可以直接返回本地结构化答案。
- 外部模型即使不可用，也不再直接导致该类问题失败。
