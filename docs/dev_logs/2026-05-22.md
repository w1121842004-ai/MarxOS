## 今日主题

今天的主要工作不是新增功能，而是把项目从“能跑但主入口很重”继续推进到“结构清楚、可长期维护”的状态。

这一轮整理覆盖了四条线：

1. `app.py` 继续拆薄
2. `web_app.py` 持续收口
3. `README / docs / scripts` 统一整理
4. 回归与审计入口补齐

## 2. `web_app.py` 侧继续收口

### 新增模块

- `marxos/web/support.py`
- `marxos/web/followups.py`
- `marxos/web/citations.py`

### 拆分内容

`marxos/web/support.py`：

- metrics 日志写入

- history 摘要
- contextual query 构建
- follow-up 判断
- Web 响应 payload 拼装

`marxos/web/followups.py`：

- 专题追问改写
- 条目解释
- 专题历史追问整理
- 专题证据排序/筛选

`marxos/web/citations.py`：

- citation line 解析
- requested citation index 识别
- OCR 原页读取
- printed page -> pdf page 定位
- 原页摘录 follow-up
- 证据页码 follow-up

### 当前效果

- `web_app.py` 下降到约 `763` 行
- Web 层结构现在比较清楚：
  - `web_app.py`: 入口
  - `marxos/web/support.py`: 通用辅助
  - `marxos/web/followups.py`: 专题追问
  - `marxos/web/citations.py`: 引文/页码追问

## 7. 当前判断

到今天为止，项目已经从“核心逻辑高度堆叠在 `app.py` / `web_app.py`”过渡到“主入口 + 多个职责明确模块”的状态。

现在最重要的收益不是代码更漂亮，而是：

- 更容易定位问题
- 更容易做局部修改
- 更不容易因为小改动牵扯整条主链
- 更方便继续补测试和文档
